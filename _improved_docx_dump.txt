0048|Heading 1|Περίληψη
0049|Normal|Η παρούσα εργασία παρουσιάζει τον σχεδιασμό και την υλοποίηση ενός συστήματος πολλαπλών πρακτόρων (multi-agent system) για την αυτοματοποιημένη ανίχνευση και επιδιόρθωση ευπαθειών κώδικα. Το σύστημα, με τίτλο Agentic SonarQube Pipeline, ενσωματώνει τεχνολογίες στατικής ανάλυσης κώδικα (SonarQube) με μεγάλα γλωσσικά μοντέλα (LLMs) σε μια πλήρως ενορχηστρωμένη αλυσίδα εργασιών (pipeline).
0050|Normal|Η αρχιτεκτονική βασίζεται σε πέντε εξειδικευμένους πράκτορες: τον Fixer Agent που εφαρμόζει χειρουργικές διορθώσεις μέσω tool calling, τον Tester Agent που παράγει και εκτελεί unit tests σε πραγματικό χρόνο, τον Reviewer Agent που αξιολογεί την ποιότητα του κώδικα μέσω structured outputs, τον Evaluator Agent που βαθμολογεί κάθε διόρθωση και αποφασίζει αν γίνει δεκτή (PASS/RETRY/FAIL), και τον Coordinator που ενορχηστρώνει τη συνολική ροή με μηχανισμό αυτο-βελτίωσης (AI reflection loop).
0051|Normal|Η μεθοδολογία ακολούθησε σταδιακή ανάπτυξη σε τέσσερις φάσεις: (1) θεμελίωση υποδομής και διασύνδεση API, (2) ενσωμάτωση LLM και τηλεμετρία, (3) πράκτορες διασφάλισης ποιότητας, και (4) ενορχήστρωση και αυτο-βελτίωση. Το σύστημα παρέχει τρεις τρόπους χρήσης: γραμμή εντολών (CLI), REST API (FastAPI), και γραφική διεπαφή (Streamlit dashboard). Η ανάπτυξη γίνεται μέσω Docker Compose, ενσωματώνοντας την εφαρμογή μαζί με τον SonarQube server σε ένα ενιαίο containerized περιβάλλον.

0062|Heading 1|Abstract
0063|Normal|This thesis presents the design and implementation of a multi-agent system for the automated detection and repair of code vulnerabilities. The system, titled Agentic SonarQube Pipeline, integrates static code analysis technologies (SonarQube) with large language models (LLMs) into a fully orchestrated workflow (pipeline).
0064|Normal|The architecture is based on five specialized agents: the Fixer Agent, which applies surgical fixes via tool calling; the Tester Agent, which generates and executes unit tests in real time; the Reviewer Agent, which evaluates code quality through structured outputs; the Evaluator Agent, which scores each fix and decides whether it is accepted (PASS/RETRY/FAIL); and the Coordinator, which orchestrates the overall flow with a self-improvement mechanism (AI reflection loop).
0065|Normal|The methodology followed an incremental development approach in four phases: (1) infrastructure foundation and API integration, (2) LLM integration and telemetry, (3) quality assurance agents, and (4) orchestration and self-improvement. The system provides three modes of use: command-line interface (CLI), REST API (FastAPI), and a graphical user interface (Streamlit dashboard). Deployment is handled via Docker Compose, integrating the application with the SonarQube server in a unified containerized environment.
0066|Normal|Keywords: multi-agent systems, LLM, SonarQube, automated code repair, tool calling, structured outputs, AI reflection, static code analysis, Python, FastAPI, Docker

0137|Heading 3|Reflection Pattern
0138|Normal|Ο μηχανισμός Reflexion  [13] επιτρέπει αυτο-βελτίωση: (1) ο Fixer παράγει διόρθωση, (2) ο Evaluator αξιολογεί και αποφασίζει RETRY, (3) το reasoning τροφοδοτείται πίσω στον Fixer ως feedback, (4) ο Fixer παράγει βελτιωμένη διόρθωση. Χωρίς fine-tuning ή re-training.

0159|Normal|Ο μηχανισμός polling αποτελεί θεμελιώδη τεχνική στην αρχιτεκτονική του συστήματος. Όταν εκτελείται μια σάρωση (scan) στον SonarQube, ο server δεν επιστρέφει αμέσως τα αποτελέσματα. Αντ' αυτού, ο SonarQube αναθέτει την ανάλυση στο Compute Engine (CE), ένα background service που επεξεργάζεται τον κώδικα ασύγχρονα. Αυτό σημαίνει ότι η εφαρμογή δεν μπορεί απλά να περιμένει μια απάντηση — πρέπει να ρωτά επαναλαμβανόμενα τον server αν η ανάλυση έχει ολοκληρωθεί. Αυτή η τεχνική ονομάζεται polling: η μέθοδος _wait_for_ce_task() στέλνει αιτήματα HTTP στο endpoint /api/ce/activity σε τακτά χρονικά διαστήματα (π.χ. κάθε 5 δευτερόλεπτα), ελέγχοντας αν η κατάσταση της εργασίας (task status) έχει αλλάξει σε SUCCESS ή FAILED. Αν η ανάλυση δεν ολοκληρωθεί εντός ενός ρυθμιζόμενου χρονικού ορίου (configurable timeout), η μέθοδος εγκαταλείπει και επιστρέφει σφάλμα, αποφεύγοντας έτσι την αιώνια αναμονή.
